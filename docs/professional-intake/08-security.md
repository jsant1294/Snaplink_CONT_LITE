# Security and Privacy

- **Auth model**: reuses the existing PIN system (`lib/auth.ts` for contractors, `lib/agent-profiles/auth.ts` for agents) rather than the SnapLink source's public-token model — see `00-snaplink-intake-audit.md` for why a second auth system would be redundant here. Every intake route calls either `authorizeIntakeOwner()` (operator or the owning professional's own PIN) or `isOperatorRequest()` (operator only), never a raw unauthenticated path.
- **No public exposure of draft answers**: there is no unauthenticated GET anywhere in `app/api/professional-intake/`. `loadAndAuthorizeSession()` 404s before it 401s, so an unauthorized caller cannot even confirm a session id exists.
- **Server-side validation**: `normalize.ts` enforces `maxLength`/`maxItems` per question (closing the gap the SnapLink audit found — its source has *no* server-side length caps at all), strips HTML/script tags (`stripHtml()`) from every text/textarea answer before it is ever persisted, and never silently guesses an unrecognized taxonomy value — it's flagged in `flaggedQuestionIds` for operator review instead (test 9).
- **No raw stack traces / no environment leakage**: every route catches and returns a plain `{ error: string }` JSON body; none echo `error.stack` or process env.
- **No credential logging**: PINs are read via the existing `pinFromRequest()` header/query helper and never written to `answers`, `flaggedQuestionIds`, or any response body (`publicContractor()`/`publicAgentProfile()` strip `pin` before the preview/apply routes return a profile).
- **File uploads**: `app/api/professional-intake/upload/route.ts` reuses the exact 8MB + `image/*` MIME check already used by `app/api/southline/upload/route.ts` and `app/api/contractor/avatar-upload/route.ts` — no new upload infrastructure, same known limitation as those routes (MIME-only, not magic-byte sniffing — a pre-existing repo-wide pattern, not something this feature introduces or regresses).
- **Rate limiting**: not added — the existing PIN-gated routes elsewhere in this repo do not rate-limit either, and this feature's routes are no more exposed than any other PIN-gated contractor/agent route.
- **Sensitive fields never auto-publish**: `licenseInfo`/`licenseNumber`/`licenseState` are marked `sensitive: true` in the review preview and are only ever written through the explicit, operator-only apply step — never through autosave/submit.
